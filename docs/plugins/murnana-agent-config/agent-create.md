# agent-create スキル

`/murnana-agent-config:agent-create` — Claude Code のサブエージェント（`agents/<name>.md`）を、ヒアリングを先に行ったうえで、公式仕様に沿って作成・更新する。

## 使い方

- 起動は**明示的なスラッシュコマンドのみ**（`disable-model-invocation: true`）。
- `$ARGUMENTS` に「変更したコードをレビューする」のような、サブエージェントの仕事のヒントを渡せる。ヒントで答えが分かる項目は聞かれない。
- 作成先は次の 3 つから選べる。
  - プロジェクト（`<repo>/.claude/agents/`）
  - 個人（`~/.claude/agents/`）
  - プラグインの `agents/`
- 1 回の実行で作るのは 1 つだけ。
- 生成されるサブエージェントのファイル（フロントマターと本文）は**常に英語**。ヒアリングと報告は会話の言語で行う。

| Step | やること |
|---|---|
| 1 | 既存のサブエージェントと、プロジェクトの指示（CLAUDE.md、rules）を確認する |
| 2 | **ヒアリング**（設計より先に行う） |
| 3 | サブエージェントが適切かを判定する（スキルなどの方が適切なら提案する） |
| 4 | 名前とフロントマターを決める |
| 5 | 本文（システムプロンプト）を雛形に沿って下書きする |
| 6 | セルフレビュー |
| 7 | 全文を提示して**承認を待つ** → 書き込む |
| 8 | 検証し、試し方を案内する |

## ヒアリングの内容

質問はすべて AskUserQuestion で行う。呼び出しは Step 2 で最大 2 回、Step 3 で必要なときに 1 回、Step 7 の承認で 1 回。

**必ず確認する項目**（会話や引数から分からないものだけを、1 回の呼び出しにまとめて聞く）

| 項目 | 選択肢 |
|---|---|
| 仕事 | レビュー・点検 / 調査 / コマンドやテストの実行 / ファイルの変更 |
| 置き場所 | プロジェクト / 個人 / プラグイン（プラグインがあるときだけ） |
| できること（複数選択） | 読み取りのみ / ファイルの編集 / シェルコマンドの実行 / Web の取得と検索 |
| 任せ方 | 該当する依頼が来たら自動で任せる / 名前を指定されたときだけ |

**条件に当てはまるときだけ聞く項目**（当てはまらなければ既定値を使う）

| 項目 | 聞く条件 | 既定値 |
|---|---|---|
| 判定基準と資料 | リポジトリーにも会話にもない知識が必要なとき | 指定されたファイルとプロジェクトのルールから取る |
| 起動のきっかけ | 自動で任せるのに、任せる依頼と任せない依頼が分からないとき | 仕事の内容から導く |
| 報告の形式 | 報告を決まった形で受け取る相手がいるとき | 既定の報告形式 |
| モデル | 費用、速度、モデルの話が出たとき | 判断が重い仕事は `inherit`、コマンド実行や機械的な検索は `sonnet`、単純な検索は `haiku` |

名前、呼び出し側が渡すもの、報告の言語、`maxTurns` などは聞かずに既定値で決め、承認時に一覧で示す。

## 設計判断とその理由

- **なぜヒアリングを設計より先にするか** — 仕事の種類と「できること」が決まらないと、`tools` も本文の構成も決められない。先に名前やツールを決めてから聞くと、答えに合わせて作り直すことになる。
- **なぜ質問に選択肢と既定値を表で持たせたか** — Sonnet でも同じ質問を同じ順で出せるようにするため。何を聞くか、いつ聞くか、聞かないときに何を使うかを表から読み取れば済み、判断の余地を減らせる。
- **なぜ質問を AskUserQuestion に限るか** — 返信の末尾に文章で書いた質問は見落とされやすく、選択肢も選べない。`rule-create` / `skill-create` と同じ方針。
- **なぜ `tools` を必ず書かせるか** — 省略すると、`Edit`、`Bash`、`Agent` を含むすべてのツールが渡る。読み取り専用のつもりのレビュー役がファイルを書き換えられる状態になる。
- **なぜ本文の雛形を固定したか** — サブエージェントは会話履歴を受け取らず、途中でユーザーに質問もできない。そのため「入力がないときの扱い」「不明点の既定の仮定」「報告の形」が抜けると動けなくなる。雛形の節として固定し、抜けを防いでいる。
- **なぜ `AskUserQuestion` を `tools` に入れさせないか** — サブエージェントからは必ず取り除かれるツールで、書いても使えない。本文で「ユーザーに聞く」と指示すると、そこで止まる原因になる。
- **なぜプラグインでは `hooks` / `mcpServers` / `permissionMode` を使わせないか** — プラグインのサブエージェントでは、安全のため無視される。
- **なぜ代替手段を作らないか** — スキルやフックの方が適切なときは提案だけにとどめる。スキルの作成は `skill-create` の役割。
- **なぜ明示起動のみか** — ファイルを書き込むスキルで、プロジェクトに置けばチームに共有される。`rule-create` / `skill-create` と同じ方針。
- **なぜ eval を置いていないか** — 明示起動のみのスキルは自動では起動しないため、起動判定の eval が成り立たない。

## 検証（2026-11-14）

- `claude plugin validate plugins/murnana-agent-config` が通ることを確認した。
- 小さな TypeScript のプロジェクトで、`claude -p --model sonnet --plugin-dir <plugin> "/murnana-agent-config:agent-create <ヒアリングへの回答>"` を実行した（`defaultEnabled` を `true` にしたコピーを使用）。ヘッドレスでは AskUserQuestion が使えないため、回答はあらかじめ引数に書いた。
  - Sonnet が、読み取り専用の `tools`、`Inputs` / `Assumptions` / `Steps` / `Rules` / `Report` の節を持つ下書きを提示し、ファイルを書き込まずに止まることを確認した。
  - 既定値（`model: inherit` など）と未確認の質問が、返信に一覧で示された。
- 対話セッションでの AskUserQuestion によるヒアリングと、書き込み後の検証（Step 8）は未確認。

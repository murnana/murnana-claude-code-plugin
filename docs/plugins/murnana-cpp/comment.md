# C++ のコメント作成

C++ のプログラムを読んで、コメント(プログラムの中に書く説明文)や使い方の説明(Doxygen の決まった形の説明)を書いたり、いらないコメントを整理したりする機能です。

## 話しかけ方

- 「C++のコメントを書いて」
- 「この関数にDoxygenコメントを付けて」
- 「不要なコメントを整理して」

C++ のプログラムに説明を付けたいと話しかければ、「コメント」や「Doxygen」という言葉を使わなくても、この機能が自動で動きます。

決まった形で呼ぶこともできます。

- `/murnana-cpp:comment`: いま変更している C++ のファイルが対象になります
- `/murnana-cpp:comment 対象のファイル`: ファイルを指定します。部品(関数やクラス)の名前でも指定できます
- `/murnana-cpp:comment review`: いまあるコメントを見直すだけにします。使い方の説明がない部品を除いて、新しいコメントは足しません

対象が何も見つからないときは、どのファイルを扱うか聞かれます。

## 何をするか

情報ごとに、書くのにふさわしい場所があるという考え方で整理します。

| 書きたいこと | 置き場所 |
|---|---|
| どう動くか | プログラムそのもの(分かりやすい名前にする) |
| 何をするべきか | テスト(動きを確かめるためのプログラム) |
| なぜ変えたか | コミットメッセージ(変更を記録するときの説明) |
| なぜほかのやり方にしなかったか(あえてやらなかったこと) | コメント |
| 使う人との約束(渡す値、返ってくる値、起きうるエラー) | 使い方の説明 |

そのうえで、次のことをします。

- プログラムを言い換えただけのコメントや、使われていない古いプログラムを残したコメントは消します。
- 「いつ・だれが・何を直したか」という経緯のコメントは消します。経緯は変更の記録に残っているからです。
- ほかの人が使う部品には、使い方の説明を付けます。説明は、部品の一覧が書かれたファイル(ヘッダー)に一度だけ書きます。
- 「なぜほかのやり方にしなかったか」は、選ばなかったやり方、その理由、見直すときの目安の 3 つを、対象の行のすぐ上に書きます。
- 知らずに触ると壊れてしまう理由(順番を守らないといけない、など)は、変更の記録にあってもコメントに残します。
- 書き終えたら、説明の形が正しいかを道具で確かめ、問題がなくなるまで直します。

書き方はプロジェクトの決まりや、いまあるコメントに合わせます。決まりがないときは `///` で始まる形にします。コメントの言語は、そのファイルのほかのコメントに合わせます。コメントがひとつもないときは英語で書きます。

プログラムそのもの(コメント以外の部分)は書き換えません。書き換えていないことは、作業の前後を比べて機械的に確かめます。名前の付け直し、テストの追加、気づいた不具合などは、報告で提案するだけです。

著作権の表示、ほかの道具への指示が書かれたコメント(書式を整える道具や検査の道具を止める指示など)、「あとでやること」(TODO)のコメントは、消しません。

## 聞かれること

質問は、作業の途中で一度にまとめて聞かれます。

- **理由**: わざとそう書いたように見えるのに、理由が変更の記録からも会話からも分からない場所があるときに聞かれます。プログラムを読めば分かることは聞かれません。
- **あとでやること(TODO)**: 担当者や課題の番号、いつやるかの条件が書かれていないときに聞かれます。

コメントを消すときに、一つずつ確認されることはありません。消したコメントはすべて報告に並ぶので、そこで確かめてください。記録(コミット)はしないので、気に入らなければ元に戻せます。

質問できない使い方(自動で動かすときなど)では、推測で理由を書くことはせず、その場所は変えずに、質問を報告にまとめます。

## 終わったあとの報告

- 消したコメント、移したコメント、書き足したコメントの一覧
- 提案したけれど行っていない、名前の付け直しやテストの追加、気づいた不具合
- 「なぜ変えたか」を書いたコミットメッセージの案
- 残った質問
- プログラムそのものを書き換えていないことと、説明の形を確かめた結果

記録(コミット)は、頼まれたときだけ行います。

# コメントの作成と見直し

C# のプログラムに付けるコメント(人が読むためのメモ)を書いたり、今あるコメントを見直したりする機能です。

## 考え方

情報は、いちばん古くなりにくく、いちばん読まれる場所に置きます。

| 書きたいこと | 置く場所 |
|---|---|
| どう動くか | プログラムそのもの(名前の付け方や分け方で分かるようにする) |
| 何をすべきか | テスト(動きを確かめるプログラム) |
| なぜ変えたか | 変更の記録(コミットメッセージ) |
| なぜ別のやり方にしなかったか | コメント |

このため、プログラムを読めば分かることを言い直しただけのコメントは消します。分かりにくいプログラムをコメントで補っていたときは、名前の付け直しなどを提案します。
一方で、「あえてこうしていない」理由は、コメントにしか残せないので、しっかり書きます。

外から使う人向けの説明(`///` で始まる説明用コメント)は別に扱い、使い方や戻ってくる値、起こりうるエラーを書きます。

## 話しかけ方

- 「このファイルに C# のコメントを書いて」
- 「このクラスに XML ドキュメントコメントを付けて」
- 「コメントを見直して、いらないものを消して」
- `/murnana-csharp:comment 対象のファイル`

## 聞かれること

- **理由**: 変わった書き方をしている場所の理由が、プログラムや変更の記録から分からないときに聞かれます。Claude が理由を想像して書くことはありません。「あとで確かめる」といった仮の書き込みもしません。
- **あとでやること(TODO)**: 担当者や課題の番号、いつやるかの条件が書かれていないときに聞かれます。

質問できない使い方(自動で動かすときなど)では、その場所は変えずに、質問を報告にまとめます。コメントの言語は、プログラムのほかのコメントに合わせます。コメントがひとつもないときは英語で書きます。

## 結果の見方

次のことが報告されます。

- 消したコメント、移したコメント、書き足したコメントの一覧
- 提案したけれど行っていない、名前の付け直しやテストの追加
- 変更の記録に書くとよい「なぜ変えたか」の文案
- 残った質問
- プログラムそのものを書き換えていないことと、説明用コメントの書き方を確かめた結果

## 知っておいてほしいこと

- 書き換えるのはコメントだけです。プログラムそのもの(名前の付け方や分け方を含む)は変えず、直し方は提案だけします。書き換えていないことは、作業の前後を比べて機械的に確かめます。
- 変更の記録(コミット)は、頼まれない限り Claude は作りません。文案だけを出します。
- プロジェクトの設定ファイルは、頼まれない限り書き換えません。
- 自動で作られたファイル、ライセンスの表記、ほかの道具への指示が書かれたコメント、「あとでやること」(TODO)のコメントは消しません。
- この機能は、Claude の中でも速さと賢さのバランスがよいモデル(Sonnet)で動きます。古いコードや大きなクラスで、理由の読み取りが浅いと感じたときは、より賢いモデル(Opus)に切り替えてやり直してください。

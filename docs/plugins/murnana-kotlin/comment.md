# コメントの作成

Kotlin のプログラムを読んで、説明書き(コメント)を付けたり整理したりする機能です。

## 考え方

説明は、それぞれ合った場所に一つだけ書きます。

| 書くこと | 書く場所 |
|---|---|
| どうやって動くか | プログラムそのもの(名前を分かりやすくする) |
| 何をするはずか | テスト(動きを確かめるプログラム) |
| なぜ変えたか | 変更の記録(コミットメッセージ) |
| なぜ別のやり方にしなかったか | プログラムの中の説明書き |

「なぜ別のやり方にしなかったか」は、あえてやらなかったことです。プログラムには、やったことしか表れないので、説明書きに残します。

そのため、説明書きを増やすだけでなく、いらない説明書きを消したり、名前の付け直しを提案したりもします。

これは目安で、厳密な決まりではありません。その行を変える人が知らないと壊してしまう「なぜ」は、変更の記録と重なっても説明書きに残します。

使い方の説明はこれとは別に扱います。ほかの人が使う部分には、使い方の説明(KDoc という決まった書き方の説明)を付けます。

## 使われる Claude の種類

この機能は、Claude の中でも、速さと正確さのバランスがよい「Sonnet」で動くように設定しています。決まった手順に沿ってファイルを読み、直していく作業が中心だからです。

- 切り替わるのは、この機能が動いている間だけです。終わったら、もとの Claude に戻ります。
- 会社などの設定で Sonnet が使えないときや、Claude Code の「自動モード」で Sonnet に対応していないときは、もとの Claude のまま動きます。

## もっと正確にしたいとき(なくても使えます)

Kotlin のプログラムを理解する補助の道具「Kotlin LSP」(JetBrains が作っている、プログラムの中の名前や型を正確に調べる仕組み)が使えると、Claude はそれも使って調べます。たとえば、ある関数がどこから、どのように呼ばれているかを、文字の検索より正確に見つけられます。

使うには、次の2つを入れます。

1. Kotlin LSP 本体(Mac や Linux では、ターミナルで `brew install JetBrains/utils/kotlin-lsp`)
2. Claude Code の公式プラグイン(Claude Code の入力欄で `/plugin install kotlin-lsp@claude-plugins-official`)

入れていなくても、この機能はファイルを読んで同じ作業をします。次のときも、Kotlin LSP を使わずに作業します。

- ブラウザーなどから使うクラウド上の Claude Code(Kotlin LSP が動きません)
- iPhone や Android など複数の環境向けに共通のプログラムを書くプロジェクト(Kotlin Multiplatform。Kotlin LSP がまだ対応していません)

Kotlin LSP は試験段階の道具なので、見つからなかった結果は、ファイルの検索でも確かめます。

## 話しかけ方

- 「Kotlin のコメントを書いて」
- 「このクラスに KDoc を付けて」
- 「このファイルのコメントを見直して」
- `/murnana-kotlin:comment 対象のファイル`

対象を指定しなかったときは、まだ記録(コミット)していない変更のあった Kotlin のファイルが対象になります。それもないときは、どこを対象にするか聞かれます。

## 聞かれること

- **別のやり方にしなかった理由**: プログラムや変更の記録から理由が分からないときに聞かれます。分からなければ、推測で書かずに、その場所を報告します。
- **あとでやるメモ(TODO)**: 担当者や課題の番号、いつやるかの条件が書かれていないときに聞かれます。

質問できない使い方(自動で動かすときなど)では、その場所は変えずに、質問を報告にまとめます。説明書きの言葉は、すでにある説明書きに合わせます。説明書きがひとつもないときは英語で書きます。

## 変わるもの・変わらないもの

- 書き換えるのは説明書きだけです。プログラムそのものは、書式も含めて変えません。書き換えていないことは、作業の前後を比べて機械的に確かめます。
- 名前の付け直しや、「使わないでください」の印(`@Deprecated`)を付けることなど、プログラムを変える案は、報告で提案するだけです。
- 著作権の表示、ほかの道具への指示が書かれた説明書き、「あとでやる」メモ(TODO)は消しません。

## 終わったあとの報告

- 消した説明書き、移した説明書き、書き足した説明書きの一覧
- 提案したけれど行っていない、名前の付け直しやテストの追加(テストがない動きと、追加するとよいテスト)
- プログラムと食い違っている説明書き
- 変更の記録に書くとよい「なぜ」の下書き
- 残った質問
- プログラムそのものを書き換えていないことと、説明書きの書き方を確かめた結果
- Kotlin LSP を使って調べたかどうか(使わなかったときはその理由)

記録(コミット)は、頼まれたときだけ行います。

# code-reviewer

Rust のプログラムをレビューするサブエージェント。ファイルは読むだけで、書きかえない。基準と手順は [review スキル](review.md) と同じ。

## 使い方

「別の目で Rust のコードをレビューして」のように頼むと、Claude が必要に応じてこのエージェントに任せる。自分で呼ぶときは `@agent-murnana-rust:code-reviewer` で指定する。

```
@agent-murnana-rust:code-reviewer src/ をレビューして
```

見てほしいファイル、フォルダー、部品の名前、または貼り付けたコードを渡す。

- 何も渡さなかったときは、変更中の Rust のファイルがあればそれを見る。なければ、対象を尋ねる報告を返す
- `main...HEAD` のような範囲だけを渡しても、このエージェントは git を動かせない。変えたファイルの一覧を一緒に渡す

## review スキルとの使い分け

| | [review スキル](review.md) | code-reviewer |
|---|---|---|
| 動く場所 | いまの会話の中 | 別の場所（会話の内容は見えない） |
| 向いている場面 | 会話の流れをふまえて見てほしい。差分（変えた行）を中心に見てほしい | 会話に左右されない別の目がほしい。たくさんのファイルを読ませて、結論だけほしい |
| git | 読み取りだけ使う | 使わない。ファイルをそのまま読む |
| 質問 | できる | できない。仮定を報告に書く |

## 報告の形式

review スキルと同じ形で、1 つの報告を返す。

```
結果: High <件数> / Medium <件数> / Low <件数>(対象: <見たファイル>)

## 使用した基準
## 指摘
## 確認できなかった点・前提
## 検証方法
```

## 設計

### 読み取り専用

ツールは `Read`、`Grep`、`Glob` に限定している。`Bash` を渡すと、読み取り以外の操作もできてしまうため渡していない。その代わり、差分ではなくファイル全体を読む。

### review スキルを読み込む

フロントマターの `skills` に `murnana-rust:review` を指定し、起動するときにスキルの全文を読み込ませている。プラグイン名を付けずに `review` と書くと、ほかの同じ名前のスキルが読み込まれることがあったため、プラグイン名を付けている。基準を 1 か所にまとめ、スキルとエージェントで食い違わないようにするため。スキルが読み込まれていないときは、記憶でレビューせず、その旨を報告して止まる。

### モデルは `inherit`

レビューは判断の重い作業なので、会話で使っているモデルをそのまま使う。Sonnet の会話から呼んでも動く。

### 呼び出し側の前提に乗らない

「問題ないよね？」「名前だけ見て」と渡されても、その結論は採らず、片づけ忘れ（メモリーリーク）の確認を必ず行う。プロジェクトの決まりも、渡された要約ではなくファイルを読んで確かめる。別の目としての価値がなくなるため。

### 途中で質問しない

サブエージェントは質問できない。分からないことは既定の仮定で進め、報告の「確認できなかった点・前提」に書く。

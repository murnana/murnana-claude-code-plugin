# Rust のコメント作成

Rust のプログラムを読んで、コメント(プログラムの中に書く説明文)を書いたり、いらないコメントを整理したりする機能です。

## 話しかけ方

- 「Rustのコメントを書いて」
- 「このモジュールにドキュメントコメントを付けて」
- 「不要なコメントを整理して」
- `/murnana-rust:comment 対象のファイル`

対象のファイルや部品の名前を言わなかったときは、まだ記録(コミット)していない変更のあった部分が対象になります。

## 何をするか

情報ごとに、書くのにふさわしい場所があるという考え方で整理します。

| 書きたいこと | 置き場所 |
|---|---|
| どう動くか | プログラムそのもの(分かりやすい名前にする) |
| 何をするべきか | テスト(動きを確かめるためのプログラム) |
| なぜ変えたか | コミットメッセージ(変更を記録するときの説明) |
| なぜほかのやり方にしなかったか(あえてやらなかったこと) | コメント |

ただし、この振り分けは覚えやすくするための目安です。その行を直す人が知らないと困る理由は、コミットメッセージに書いたうえで、コメントにも残します。

そのうえで、次のことをします。

- プログラムを言い換えただけのコメントは消します。
- ほかの人が使う部品には、使い方の説明文(ドキュメントコメント)を付けます。説明文の中の使い方の例は、実際に動かして確かめます。
- 「なぜほかのやり方にしなかったか」は、コメントとして残したり書き足したりします。選ばなかったやり方、その理由、どうなったら見直してよいかの3つを書きます。
- 「あとでやること」(TODO)のコメントは残します。課題の番号やいつやるかの条件がないときは、あなたに聞きます。

プログラムそのもの(コメント以外の部分)は書き換えません。書き換えていないことは、作業の前後を比べて機械的に確かめます。名前の付け直しやテストの追加は、提案だけして、あなたが了解したときに行います。

`SAFETY:`(安全である理由の説明)、著作権の表示、「あとでやること」(TODO)のコメントは、消しません。

## 聞かれること

- **理由**: わざとそう書いたように見えるのに、理由が変更の記録からも分からない場所があるときに聞かれます。
- **あとでやること(TODO)**: 課題の番号やいつやるかの条件が書かれていないときに聞かれます。

質問できない使い方(自動で動かすときなど)では、その場所は変えずに、質問を報告にまとめます。コメントの言語は、プログラムのほかのコメントに合わせます。コメントがひとつもないときは英語で書きます。

## 終わったあとの報告

- 消したコメント、移したコメント、書き足したコメントの一覧
- 提案したけれど行っていない、名前の付け直しやテストの追加
- 「なぜ変えたか」を書いたコミットメッセージの案
- 残った質問
- プログラムそのものを書き換えていないことと、説明文の例を動かして確かめた結果

記録(コミット)は、頼まれたときだけ行います。

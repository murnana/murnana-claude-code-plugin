# test-case-writer

Rust のプログラムに対するテストを書いて、報告を 1 つ返すサブエージェント(Claude が仕事の一部を任せる、別の Claude)です。変えるのはテストだけで、プログラム本体は変えません。

## 使い方

「このファイルのテストを書いておいて」のように頼むと、Claude が必要に応じてこのエージェントに任せます。明示的に呼ぶときは `@agent-murnana-rust:test-case-writer` で指定します。

```
@agent-murnana-rust:test-case-writer src/shipping.rs のテストを書いて
```

渡すもの:

- **対象**(必須): ファイル、クラス、関数、またはフォルダー。渡さなければ、対象がないことを報告して止まります。
- **仕様**(あれば): そのプログラムが何をするべきか。渡さなければ、説明書き(ドキュメントコメント)、文書、いまあるテスト、呼び出している側のプログラムを仕様として読みます。

## スキルとの使い分け

| | [test-case スキル](test-case.md) | test-case-writer |
|---|---|---|
| 動く場所 | いまの会話の中 | 別の Claude(会話の内容は見えない) |
| 質問 | 途中で質問する | 質問しない。決められた前提で進め、報告に書く |
| プログラム本体 | 頼まれれば実装もする(TDD) | 変えない |
| 向いている仕事 | 仕様を相談しながら進める、TDD で作る | すでにあるプログラムに、まとめてテストを足す |

## 報告の形式

1. 全体の結果(1 行)
2. 前提(呼び出し側が伝えたものと、エージェントが決めたものを区別する)
3. テストリスト
4. 書いたテスト
5. 不具合の疑い(期待した値とその根拠、実際の値、ファイルから外したテストの全文)
6. テストにしなかった動き(答えてほしい質問、またはテストしやすくするための直し方)
7. 動かしたコマンドと結果(動かせなかったときは、その旨)

## 設計

### サブエージェントにした理由

すでにあるプログラムにテストを足す仕事は、対象のファイル、呼び出している側、いまあるテストをたくさん読みます。その中身は、もとの会話には必要ありません。報告だけを受け取れば足りるので、別の Claude に任せる形にしました。

### プログラム本体を変えず、不具合は報告にする理由

質問ができないので、「プログラムが間違っているのか、仕様の読み方が間違っているのか」をその場で確かめられません。仕様どおりのテストが失敗したときは、テストをファイルから外して全文を報告に載せます。テストを残すと全体のテストが通らなくなり、消してしまうと見つけたことが失われるためです。

### 「問題ないはず」という頼み方に乗らない理由

「動いているから、テストだけ足して」と頼まれると、いまの動きを正解にしたテストを書きたくなります。それでは不具合を見つけられないので、期待する値は必ず仕様から決めます。

### ツールとモデル

- ツールは `Read`、`Grep`、`Glob`、`Edit`、`Write`、`Bash` です。`Bash` はテストを動かすコマンドと `git status`、`git diff` にだけ使うよう、本文で決めています。道具を入れること、記録(コミット)すること、通信することは禁じています。
- モデルは `inherit`(呼び出した側と同じ)です。テストケースを選ぶのは判断の多い仕事だからです。Sonnet で呼び出されても手順を飛ばさないよう、手順に番号を付け、分からないことの決め方を表にしています。
- 本文には、スキルと同じ決まりをまとめ直して入れています。サブエージェントは、もとの会話も、読み込まれたスキルも見えないためです。

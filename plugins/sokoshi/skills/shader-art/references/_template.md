# 知識ファイルテンプレート

カテゴリごとに4種のテンプレートがあります。新しい知識を追加する時はコピーして使ってください。

ファイル名は **kebab-case + 内容が一目で分かる名前** にしてください。Claudeはファイル名一覧を見て読むファイルを選ぶため、名前が曖昧だと該当判定の精度が落ちます。

良い例: `raymarching-template.md`, `n+1-frag-fetches.md`, `webgl-precision-loss-on-mobile.md`
悪い例: `note-001.md`, `tips.md`, `memo.md`

---

## technique テンプレート(`techniques/<name>.md`)

```markdown
# <技法名>

## 概要
1〜2文でこの技法が何をするものかを書く。

## 数式の意図
この技法の背後にある数学・幾何学的アイデアを説明。読者がコードだけでなく
「なぜ動くか」を理解できるようにする。

## 最小コード断片(GLSL)
\`\`\`glsl
// 最も短く、本質だけ示すコード
\`\`\`

## 使い所
- どんな表現を作りたい時に使うか
- どんな技法と組み合わせると効果的か

## 落とし穴
- 数値精度の問題
- パフォーマンス特性
- よくある誤用
```

## pattern テンプレート(`patterns/<name>.md`)

```markdown
# <パターン名>

## どんな見た目になるか
1〜2文で結果の見た目を描写。

## 使う技法
- techniques/X.md
- techniques/Y.md
を組み合わせる。

## レシピ(GLSL)
\`\`\`glsl
// 実際に動くコード断片
\`\`\`

## 調整可能なパラメータ
- パラメータ名: 何を変えるとどう見た目が変わるか

## バリエーション
このパターンから派生できる他のエフェクトのアイデア。
```

## gotcha テンプレート(`gotchas/<name>.md`)

```markdown
# <症状を一言で>

## 症状
何が起きるか(どう見えるか・どう動かないか)。

## 原因
なぜそれが起きるかの根本原因。

## 検出可能なパターン
コードレビュー時に該当判定するための特徴。Claudeはまずこのセクションだけを
読んで該当性を判定する設計なので、**具体的なキーワード・正規表現的な特徴**を
挙げること。

例:
- `texture2D(channel0, uv)` を `mainImage` 内で多用している
- `mod(x, 1.0)` で負の値の x を扱っている
- `length(vec3(...))` を `if` 内で重複呼び出ししている

## 修正パターン
\`\`\`glsl
// Before
...
// After
...
\`\`\`

## 関連
- techniques/X.md(関連技法)
- targets/Y.md(該当環境)
```

## target テンプレート(`targets/<name>.md`)

```markdown
# <環境名>

## ボイラープレート
\`\`\`glsl
// この環境で必要な最小コード
\`\`\`

## 組み込みuniform/関数
- `iResolution` / `gl_FragCoord` 等、その環境で使えるもの

## 制約・特徴
- precision宣言の要否
- マルチパスの有無
- 利用可能なテクスチャの種類

## デバッグ手段
- 色をassertとして使う
- どこを見れば数値の異常がわかるか

## 他環境との差分(移植時のチェックリスト)
- entry point: 〜
- uniform名: 〜
- precision: 〜
```
